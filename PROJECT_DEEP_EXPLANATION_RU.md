# Подробный разбор проекта `employees-fe` (очень простыми словами + теория)

## 1. Что это за проект вообще

Этот проект — это **веб-приложение на React + TypeScript + Vite**.

Если объяснить совсем просто:
- есть “страничка-домик”;
- у домика есть меню сверху (`Home`, `Add Employee`, `Statistics`);
- при нажатии на меню меняется “комната” (страница), но **весь дом не перезагружается**;
- пока страницы в основном как таблички с надписью (заглушки), то есть логика еще не доделана.

Такой формат называется **SPA (Single Page Application)**.

## 2. Главная идея SPA (Single Page Application)

Обычный сайт:
- нажал ссылку;
- браузер заново загружает целую HTML-страницу с сервера.

SPA:
- HTML загружается один раз;
- дальше React сам меняет кусочки интерфейса;
- переходы быстрее и плавнее.

В этом проекте за переходы отвечает `react-router-dom`.

## 3. Карта проекта (что где лежит)

### Корень проекта

- `package.json` — список зависимостей и команд (`dev`, `build`, `lint`).
- `index.html` — единственная HTML-точка входа с `<div id="root">`.
- `vite.config.ts` — настройки Vite.
- `tsconfig*.json` — настройки TypeScript.
- `eslint.config.js` — правила проверки кода.
- `Employee.ts` — тип данных сотрудника (модель).

### Папка `src`

- `main.tsx` — запуск React-приложения.
- `index.css` — глобальный CSS (сейчас там стиль активной ссылки).
- `components/router/routes.tsx` — схема маршрутов (какие страницы существуют).
- `components/pages/*` — страницы и layout.
- `components/ui/*` — UI-утилиты Chakra (theme provider, toaster, tooltip, color mode).

## 4. Как приложение “оживает” после запуска

Путь от “пусто” до “всё работает”:

1. Браузер открывает `index.html`.
2. Внутри есть `<div id="root"></div>`.
3. Скрипт `src/main.tsx` запускается и говорит React: “рисуй приложение внутри `root`”.
4. React оборачивает приложение в:
   - `StrictMode` (режим поиска потенциальных проблем),
   - `Provider` (Chakra UI + тема),
   - `RouterProvider` (маршруты/навигация).
5. Роутер решает, какую страницу показать по текущему URL.

## 5. Разбор `main.tsx`

`main.tsx` — это кнопка “Старт”.

Он делает важные вещи:
- импортирует React/DOM;
- импортирует CSS;
- подключает `router`;
- оборачивает приложение в провайдеры.

Ключевая мысль:
- **без `RouterProvider` не будет роутинга**;
- **без Chakra `Provider` не будут корректно работать темы/стили Chakra**.

## 6. Что такое роутинг (routing)

**Роутинг** — это правило: какой URL показывает какой компонент.

Пример:
- `/` → `HomePage`
- `/add` → `AddEmploeePage`
- `/statistics/age` → `AgeStatisticsPage`

В проекте роуты объявлены в `src/components/router/routes.tsx`.

### 6.1 `createBrowserRouter`

`createBrowserRouter([...])` принимает массив объектов-маршрутов.

У каждого маршрута обычно есть:
- `path` — путь в адресной строке;
- `element` — какой React-компонент рендерить;
- `children` — вложенные маршруты.

### 6.2 Вложенные роуты

Есть главный маршрут `/`, у него `element: <LayoutPage />` и `children`.

Это означает:
- `LayoutPage` рисуется всегда для всех вложенных страниц;
- внутри `LayoutPage` место для дочерней страницы определяет `<Outlet />`.

## 7. Что такое Layout и зачем нужен `Outlet`

**Layout** — это общий “скелет” страниц.

В этом проекте `LayoutPage`:
- сверху показывает `AppBar` (меню);
- ниже показывает текущую дочернюю страницу через `<Outlet />`.

Аналогия:
- Layout — это рамка/дом;
- Outlet — это окно, в которое подставляется нужная комната.

Если открыть `/statistics/salary`, то:
- сначала рисуется `LayoutPage`;
- внутри его `Outlet` рисуется `StatisticsPage` (родитель статистики);
- внутри `StatisticsPage` в его `Outlet` рисуется `SalaryStatisticsPage`.

## 8. Что такое `NavLink` и класс `.active`

В меню используется `NavLink`:
- это как `Link`, но умеет понимать “я сейчас на этой странице или нет”.

В `src/index.css` есть:

```css
.active {
  font-weight: bold;
}
```

Когда маршрут активен, `NavLink` получает класс `active`, и ссылка становится жирной.

## 10. Chakra UI и зачем нужен Provider

`@chakra-ui/react` — библиотека готовых UI-компонентов:
- `Box`, `Text`, `HStack`, `VStack`, `IconButton`, и так далее.

Плюс:
- быстро собирать интерфейс;
- единый дизайн;
- удобная тема (цвета, размеры, типографика).

`Provider` в `src/components/ui/provider.tsx` подключает:
- `ChakraProvider` (дизайн-система Chakra);
- `ColorModeProvider` (светлая/темная тема через `next-themes`).

Без этого компоненты Chakra могут работать некорректно или без темы.

## 11. Цветовые темы (`color-mode.tsx`)

В `color-mode.tsx` лежат:
- `ColorModeProvider` — подключает `next-themes`;
- хук `useColorMode` — получить текущую тему и переключать;
- `ColorModeButton` — готовая кнопка смены темы;
- `useColorModeValue(light, dark)` — выбрать значение по теме.

Текущий проект пока не выводит кнопку переключения темы на экран, но инфраструктура уже есть.

## 12. Toaster и Tooltip

### `toaster.tsx`

Toaster — это всплывающие маленькие уведомления:
- “Сохранено”;
- “Ошибка”;
- “Загрузка...”

В файле создан:
- объект `toaster` (настройка позиции и поведения);
- компонент `Toaster` (контейнер отображения сообщений).

Пока не подключен в `main.tsx` или layout, поэтому уведомления визуально не используются.

### `tooltip.tsx`

Tooltip — это подсказка при наведении.

Файл содержит обертку над Chakra Tooltip, чтобы проще использовать в проекте:
- можно включать/выключать стрелку;
- можно рендерить через `Portal`;
- можно отключить tooltip флагом `disabled`.

## 13. Типы и модель данных (`Employee.ts`)

`Employee` — это TypeScript-тип (форма объекта сотрудника):
- `id?: string`
- `fullName: string`
- `salary: number`
- `birthdate: string`
- `department: string`
- `avatar?: string`

Что важно:
- `?` означает “поле необязательное”;
- TypeScript проверяет, чтобы ты случайно не отправил, например, `salary: "abc"` вместо числа.

Сейчас этот тип не подключен к страницам, но он очень полезен для будущей формы и API.

## 14. Теория: ключевые термины простыми словами

### Компонент (Component)

Функция, которая возвращает JSX (описание интерфейса).

Пример:
- `HomePage` — это компонент.

### JSX

Синтаксис похож на HTML внутри TypeScript/JavaScript.

### Props

Входные параметры компонента (как аргументы функции).

### State

Внутренние данные компонента, которые могут меняться со временем.

В этом проекте `useState` почти не используется, потому что логика пока минимальная.

### Hook

Спец-функция React (`useState`, `useEffect`, `useMemo` и др.), которая дает возможности состояния и жизненного цикла.

### Route

Правило “URL -> компонент”.

### Nested Route

Маршрут внутри маршрута, рендерится через `Outlet`.

### Layout Route

Родительский маршрут для общего каркаса страниц.

### Provider (Context Provider)

Компонент, который “раздает” данные всем дочерним компонентам (тема, локаль, auth и т.п.).

### StrictMode

Режим разработки React для выявления проблем; в production он не добавляет UI.

## 16. Почему проект называется `employees-fe`

`fe` обычно означает **front-end**.

То есть это клиентская часть системы сотрудников.
Обычно рядом бывает `employees-be` (backend/API), но здесь его нет.
